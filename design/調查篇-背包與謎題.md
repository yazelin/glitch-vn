# 《調查篇》背包與謎題（2026-09-06，為第二屆創作者挑戰立的）

這一份把 2026-09-06 談定的事寫成一處。它不取代 `調查篇.md`、`調查篇-場景.md`、
`調查篇-信心.md`，只補那三份沒有的兩件事：背包插件怎麼接進來，以及玩家在哪裡交答案。
變數的新增在第七節，要合併回 `調查篇-變數.md`。

**調查篇開成一個新的 Larch 專案，不接在正文那個專案裡**（正文 id 在 `larch/config.py`，
調查篇的 id 建好之後另外記，兩個不要混）。背包插件在新專案的 `settings.plugins` 裡開。

**動筆前照舊先讀 `調查篇.md` 的「零、這個故事在講什麼」。** 這一份每一格的判準沿用那一節：
這一格有沒有在講「重複」或者「被記住」。

## 一、今天拍板的

1. **記錄用書，手機只收不記。** 理由三條正典一條省工：結局「這是我的字」只有手寫成立；
   她一格一格「抄」跟格莉奇每天抄一次是同一個動作；這個世界裡看手機是別人的標記
   （保全講黑洞先生：「等人的會看手機，一直看。他不看」）；現有 `notes.html` 就是筆記本。
2. **她寫筆記的那本，就是她買的守則本周邊。** 一千二，皮面、很厚、內頁空白、附印簽名的書籤。
   宣傳文案說「第一頁我每天抄七個人」「你可以自己寫」。她在她的本子裡用她的方法抄人。
3. **背包一開始兩件：守則本、手機。** 不播獲得動畫。
4. **錄音機是動作不是道具**，錄下來的段落才進背包。錄音機本身照第一天定稿：轉盤會卡，
   諾亞說「不用修，裡面有毛」。
5. **跨場景新用途做兩件**：錄音（播回去比對、播給第三個人）、筆記本（拿給人看、並排比）。
6. **結局那一頁玩家自己填**：六個 ID 各對到一個人，第七行鎖死。填錯不罰，筆記照她填的記。
7. **第六格（考完就刪）是不在場的名字**，對不到任何見過的人。這一格照 `調查篇-場景.md`
   「第六個名字」那一節，遊戲不確認、不推翻。
8. **主角動機維持「本就在收異常」**，職業不寫。守則本的文案給她的是一個可以驗證的數字，七，
   而她的興趣早在買它之前。
9. **她不找格莉奇本人。** 會忘的人不能替自己作證，能作證的是被她記得的六個人。
   這一條是「直到最後都不能見到他們兩個」的正典解釋，關卡設計只是照著它排。

## 二、背包

### 二之一、裡面有什麼

| 道具 | 進來的時機 | 拿得出來用嗎 | 備註欄寫什麼 |
|---|---|---|---|
| 守則本 | 開場就在 | 在指定場景的 open-bag 卡裡挑 | 「一千二。第一頁還是空的。」隨進程改（見四之三） |
| 手機 | 開場就在 | 不能用，只收（第五節） | 「沒有人會打來。」 |
| 錄音・某人・第 N 天 | 那一場結尾 | 在指定場景的 open-bag 卡裡挑 | 錄到的那一句，原文 |

**不做的**：卡帶容量上限（讓她像格莉奇一樣「裝不下要選留哪一段」很誘人，可是那是把正文的核心機制
再演一次，而且多一套 UI；等有人玩完覺得錄音太多再說）、手機拍照（照片是客觀證據，會把
「旁白客觀、筆記主觀」那個時間差抹平）、錄音機本身當道具（它已經是進頂樓的通行證，
再進背包就要處理 HUD 隨時「使用」它的問題，收益是零）。

### 二之二、跟平台的對接

平台事實見 `~/.claude/skills/larch-vn/SKILL.md` 「背包（larch-inventory）」與「背包插件」兩節。

- **HUD 常駐，玩家隨時能按。** 所以劇情裡每一次「打開包包」都用 `open-bag` 卡，
  `allowSkip` 一律 `true`，沒有一張是死路。
- **分支靠 `pickVar`**（預設 `inventoryLastUsed`）：玩家挑了哪一段錄音，下一張卡就播哪一句。
  它寫進去的是**道具名稱**不是 id（第八節第三條）。「有沒有某段錄音」用出邊條件 `hasItem` 判。
- **道具全部 `consumable:false`**，錄音播過不會消失。
- **`storyNodeId` 全部留空。** HUD 直接「使用」只寫變數不換卡（第八節第二條）。
  守則本的「使用」接一張 interrupt 卡翻出筆記再回原處（第八節第八條）；手機用使用條件鎖死（第九條）。
- **`grant-item` 的獲得動畫只給錄音用。** 守則本與手機開場就在，用變數初始值塞進 `inventory`
  （第八節第一條要先驗這件事做不做得到；做不到就在開場第一張旁白之後補兩張 `grant-item`，
  `hideAfterCollect:true`）。
- **`open-bag` 那張卡沒有 iframe**，對話框裡會留一塊 `#111` 的區塊，透明法對它無效，
  只能調對話框尺寸。這一塊視覺上要接受。

## 三、錄音

### 三之一、來源

錄音機第一天就在她包包裡，轉盤會卡，她一直想修沒去修（`調查篇-第一天-定稿.md` 一之一）。
管理員看一眼放她上頂樓，諾亞拆開說「這個不用修。裡面有毛。頭髮。你放口袋放太久了」。
**從那一場結尾起錄音機能用**（`rec_ok = true`）。

沒去頂樓的玩家錄不了音。頂樓是第一天下午就開的地點，而且提示寫在板上，所以這不是死路，
只是晚一點。

### 三之二、誰給錄，誰不給

**設計原則：給不給錄，是這個人跟「被留下來」的關係。** 跟目擊描述一樣，每個人的答案是他自己的自畫像。

| 人 | 給不給 | 他怎麼說 | 錄到的那一句 |
|---|---|---|---|
| 管理員 | **不給**，不生氣 | 「收起來。住戶的事我不講，錄了也一樣。」 | — |
| 諾亞 | **給**，不在意 | 「錄什麼。收音機才要錄。」 | 「因為她每次都是第一次問啊。」兩天兩份 |
| 斑比 | **下午不給，深夜給** | 下午：「客戶的事我不談，錄了更不談。」深夜：「隨便。」 | 「她記得畫面，記不得上一版。」 |
| 鐵塔 | **兩處都不給** | 錄音間門口：「這裡不能錄音。」便利商店深夜：「你錄，我就走。」 | — |
| 0x | 碰不到 | 櫃檯：「本公司不接受錄音。」歸進 `deadend_pr`，不另加卡 | — |
| 保全 | **給**，而且講得更多 | 「錄啊。十年沒有人問過我。」 | 「監視器上常常有一個人站在對面。我沒下去問過。」 |
| 貓草 | **絕對不給** | 「你錄音？」然後那一場當場結束 | — |
| 便利商店店員 | **給**，無所謂 | 「可以啊。」 | 「他買過東西嗎……我不確定他有沒有進來過。」 |
| 材料行老闆 | **給**，只講零件 | 「錄零件的事可以。」 | 「有一個穿西裝的來問過真空管。是不是他我不知道。」 |
| 路人 | 不問 | — | — |

三條硬規矩：

1. **鐵塔那兩場維持沒有錄音。** 便利商店深夜那一則筆記已經定稿：「這句話我用不了。沒有錄音，
   也沒有第二個人聽到。」錄音機在她包包裡、能用、她沒拿出來，因為他說了「你錄，我就走」。
   這一句要補進那一場，補在他第一句話之後。
2. **貓草那裡開錄音機掉信任一級**，而且那一場立刻結束（`slot` 照常往前）。階三那一晚
   （「你不要寫出去喔」）不出現錄音選項。那一頁刻意留白的規矩延伸到聲音：她答應過他。
3. **給錄的人，錄與不錄的台詞一個字都不差。** 只多一張 talk 卡放他對錄音機的反應。
   這樣「同一份錄音」那個技法（`調查篇-橋段2.md` 六）不受影響，卡片經濟只多一張。

### 三之三、錄音的動作怎麼演

錄音的選項只出現在上表「給」的那幾場，而且 `rec_ok` 為真。選擇卡兩個選項：
「開錄音機」「不開」。開了，那一場結尾多一張 `grant-item`（錄音・某人・第 N 天），
獲得畫面用的圖是一顆卡帶，五個人共用一張。

**選項不出現在管理員、鐵塔、貓草那幾場。** 不給錄的人，是她自己判斷不該拿出來，
那一場的旁白寫一句「錄音機在包包裡」就夠，那是她的判斷不是系統擋她。
唯有第一次在貓草面前她可以拿出來（階零到一之間），那是她學到規矩的那一次。

### 三之四、錄音在別處派上的用場

**用途甲：兩段並排（重複的證明）。** 諾亞的「因為她每次都是第一次問啊」錄兩次，
中間至少隔一天。第二次錄完那一場結尾，open-bag 卡讓她挑一段播，播的是**同一份音檔**
（鍵同、情緒欄同）。筆記：

> 兩段。同一句。停頓在同一個位置。他沒有在背，他每次都是這樣講。

寫 `clue_same_pause`。**這是全作唯一一次，玩家親耳聽到「重複」被證明。**
旁白不加話。

**用途乙：播給第三個人。** 保全那一段拿到一樓播給管理員。

> **管理員**：（聽完）監視器。
>
> **管理員**：他都走樓梯。監視器照不到樓梯。

寫 `see_stairs`。管理員這一句跟他自己的目擊描述「他都走樓梯」是同一句，第二次出現。

不做更多用途。兩個夠滿足官方那條，多做就是為了背包而背包。

## 四、筆記本，也就是守則本

### 四之一、它是什麼

她買的周邊。皮面深色、厚到已經不太像筆記本、內頁全空、書籤印著簽名。
她拿它當調查筆記，因為文案說「你可以自己寫」，而她要驗的數字就印在文案上。

`notes.html` 那張卡不改名（「調查筆記」），封面圖改成守則本的樣子。

### 四之二、在別處派上的用場

| 場 | 用法 | 已有還是新增 |
|---|---|---|
| 一樓，管理員的失物籃 | 籃子裡那本拿出來跟她自己那本並排。四個角磨得一樣，籃子裡那本邊角更白，被拿出來又放回去很多次 | 已有那一場（`調查篇-橋段2.md`），加一張 open-bag 與一張旁白 |
| 頂樓，諾亞 | 把一樓抄的十一格信箱名字翻給他看。他指一格：「這個搬走了。」筆記照她原本抄的留著，旁邊加一個問號 | 新增，`trust_諾亞 >= 1` |
| 斑比工作室那面牆 | 她把自己那本翻到第一頁，照著截圖抄六個 ID。這是六個名字第一次進她的筆記 | 已有那一場（`trust_斑比` 3），加一張 open-bag |

第二條是筆記「可以寫錯」第一次被外人碰到。諾亞沒有幫她改，他只講他知道的事。

### 四之三、備註欄隨進程改

背包裡守則本那一件的備註是她對這本書的態度，三段：

| 條件 | 備註 |
|---|---|
| 開場 | 「一千二。第一頁還是空的。」 |
| `names_seen` | 「第一頁抄了六個。第七行她寫的是不要問。」 |
| 收尾那一場 | 「倒數第三頁有一行我不記得寫的字。」 |

備註改不了現有道具，只能刪掉再給一次；`grant-item` 的 `hideAfterCollect` 配 `itemId` 相同
能不能覆寫，第八節第五條要驗。驗不過就只留開場那一句。

## 五、手機

**只收，不能回，不能查。** 她回不了任何人，也沒有人等她回。

| 什麼時候響 | 內容 | 用哪張卡 |
|---|---|---|
| 晚上時段開板時，她開台的日子 | 「格莉奇 開始直播了」 | 格莉奇手機插件的通知橫幅卡 |
| `trust_斑比` 到 2 那一場之後 | 斑比：「有空來工作室。稿子帶著。」這就是「她約你」，`open_studio` 由這一則打開 | 通知橫幅卡 |
| 十四樓櫃檯之後 | 公關窗口自動回覆：「您的來信已收到，我們將於三至五個工作天內回覆。」永遠沒有下一則 | 通知橫幅卡 |

不用聊天卡，只用橫幅。聊天卡有輸入框，而她不能回。

**不會傳訊的人**：貓草（他不會給號碼）、諾亞（沒有手機）、鐵塔（他的號碼她拿不到）、管理員、保全。

手機在背包裡是為了兩件事：官方要「背包系統」看得見，以及第一天定稿那句
「站牌下面站著五個人，四個在看手機」有對照，她的手機在包包裡。

## 六、謎題

### 六之一、三道題

| 題 | 玩家要弄懂什麼 | 主角弄懂了嗎 | 從哪裡拿線索 |
|---|---|---|---|
| 一、六個 ID 各是誰 | `@CatGrass_80` 貓草、`@Tower_Manager` 鐵塔、`@Null_0x99` 0x、`@Bambi_Draft3` 斑比、`@Radio_Noah` 諾亞 | 弄懂五個 | ID 從斑比牆抄來；對人靠證詞（等級八十、第四十版、修收音機的、經紀人、十四樓那家） |
| 二、第六個 ID 是誰 | `@考完就刪` 對不到任何見過的人。開台第一天在、話最多、某天沒了、沒回來 | 停在跟她一樣的位置 | 只有貓草階三那一段 |
| 三、第七行是誰 | 六份互相矛盾的目擊講的是同一個人，而且是她每天點頭的那位 | **沒有**，她寫「還有一個」 | 旁白每一次擦身而過的描述；`hole_sightings` |

第三題是給玩家的，遊戲不讓她填。這一條同時是規則、主題，以及互評玩家會寫進「驚喜文字」的東西。

### 六之二、交答案的那一頁

`notes.html` 加一頁「第一頁」，**`names_seen` 之前不出現**。七行：

- 前六行左邊是 ID（照牆上抄的順序），右邊一個下拉，選項是她見過的人（`met_*` 為真的）
  加一個「查不到」。
- 第七行沒有下拉。左邊印她在牆上看到的那一句「還有一個。不要問他是誰。」，右邊是她自己的字：
  「還有一個。」不能改。
- 填完不評分、不對答案、不出任何提示。旁白只把她填的照唸一遍（照她寫的唸，包括錯的）。
- 收尾那一場翻本子的時候讀這一頁的內容進旁白。

**這一頁在收尾之前隨時可以改。** 中段的筆記本來就是劃掉的比留下的多（`調查篇-信心.md` 二）。

### 六之三、不評分這件事

謎題設計獎看的是有沒有一個讓玩家覺得「我解出來了」的地方，而這款的規矩是遊戲不評價
（貓草那一頁留白、諾亞告不告訴他，都不給獎勵）。兩件事的張力我選規矩這邊：
填對填錯，結局同一個，她都下樓跟那個人點頭。

給玩家的確認只有一個：**第七行她填不了，而玩家知道那是誰。** 那個知道就是解出來的感覺。

第九節把這一條列進「還沒決定的」，投稿前若試玩的人普遍覺得沒有解到，再回來談。

### 六之四、沒看到牆的玩家

收尾門檻是四樣都花掉，不看線索（`調查篇-信心.md` 五）。所以有人會沒到 `trust_斑比` 3 就進結局。
那時候「第一頁」那一頁不存在，收尾旁白讀的是空的第一頁：

> 第一頁。她一個字都沒有寫。

結局照樣下樓，照樣點頭。**她沒解開，可是她做完了。** 這是原案本來就允許的結果。

## 八、平台行為（2026-09-06 晚讀播放器程式碼驗過的）

讀的是 `larch.ink/assets/Preview-DmodMXUF.js`（播放器）與 `store-ByQxmw_e.js`（插件定義，背包 v1.9.0）。
**沒有在真專案上跑過**，第七條那支往返測試仍然要做。

| 條 | 結果 | 對設計的影響 |
|---|---|---|
| 一、`inventory` 初始值 | 專案變數表每一筆有 `defaultValue`（string／number／boolean）。道具 JSON 短鍵：`id, n(名稱), i(圖), d(備註), q(件數), c(可消耗), e(效果), v(效果變數), x(效果值), t(使用後前往卡)`，也吃長鍵與純字串 | 開場兩件用 `inventory` 的預設值塞，例：`[{"id":"rulebook","n":"守則本","d":"一千二。第一頁還是空的。","c":false},{"id":"phone","n":"手機","d":"沒有人會打來。","c":false}]`。**要在真專案上確認播放器開場真的讀預設值**（playerName 那一格就是這樣運作的，可信度高） |
| 二、HUD 直接「使用」`storyNodeId` 空、`consumable:false` 的道具 | 只做三件事：寫 `inventoryLastUsed`、套效果、件數不變。**不跳走、不換卡。** 唯一例外是有一張 interrupt 卡的條件剛好被它寫的變數觸發（見下） | 守則本與手機可以放心設成可使用。要讓它「翻開就是筆記」，走 interrupt（下面第八條） |
| 三、`pickVar` 寫進去的值 | **是道具名稱**（`e.name`），不是 `itemId`。略過時寫空字串，另寫 `pluginResult` 為 `used`／`skipped` | 分支條件比的是「錄音・諾亞・第三天」這種字串。**名稱一旦定了不能改**，改了條件就對不上 |
| 四、效果種類 | `none / set / add / subtract / toggle`，欄位 `effectKind / effectVar / effectValue`。**效果在「使用」時才套，取得時不套** | 拿到錄音不會自動設變數。**改用出邊條件 `hasItem` / `lacksItem`**（見第六條），第七節的 `has_rec_*` 全部拿掉 |
| 五、同一個 `itemId` 再給一次 | 解析時同 id 合併：件數相加、**後來那一件的欄位覆寫**（名稱、備註、圖） | 四之三改備註可以做，可是件數會變二。改成先 `remove-item`（移除數量 0＝全部）再 `grant-item`，兩張卡，`autoCollect:true` 不用點 |
| 六、出邊條件 | 除了變數比較，多兩個運算子 **`hasItem` / `lacksItem`**：比對 `inventory` 裡有沒有某個 id | 「有沒有錄到諾亞第二段」直接判道具，不用旗標 |
| 七、往返 | 沒驗。變數全部走播放器存檔（`larch-player-vars-<專案id>`），`inventory` 是其中一個字串 | 照原案做那支 Playwright 測試 |
| 八、interrupt 卡 | 有一種卡 `type:"interrupt"`：`interruptCondition`（變數條件）成立時插播，`interruptOnce`（預設只觸發一次，設 false 可重複，但條件要先變回不成立再成立），`interruptExit` 為 `return`（回原卡原行）／`jump`／`end` | **這是 HUD 常駐入口的正解**：守則本 `effectKind:set`、`effectVar:open_notes`、`effectValue:true`；一張 interrupt 卡條件 `open_notes == true`，內容就是 `notes.html`，`interruptOnce:false`，出口 `return`；`notes.html` 收尾 `larch:set open_notes=false`。玩家在任何一場按背包用守則本，筆記翻出來，關掉回到原處 |
| 九、道具使用條件 | 每件道具有 `useConditionVariable / useConditionValue / useConditionMessage`，不成立時按「使用」只跳訊息 | 手機設成永遠不成立，訊息「沒有人會打來。」這一句就是它的用途 |
| 十、HUD 顯示 | 變數 `inventoryHudVisible`（`auto`／true／false）加兩張卡 `show-hud`／`hide-hud` | 收尾那一場翻本子的時候把 HUD 關掉，別讓玩家在那一刻打開背包 |
| 十一、手機插件的橫幅卡 | `receive` 卡獨立可用：`contactName / avatar / messages / sound / historyVar / duration / dim / bgImage / bgColor`。不開手機、停 1 到 8 秒自動繼續 | 第五節照寫 |

**修正前面幾節的三處**：二之二「每段錄音進包包時同時把一個布林設成 true」作廢，改判 `hasItem`；
第七節 `has_rec_*` 六個變數刪掉；二之二「`storyNodeId` 全部留空，HUD 使用要先驗」已驗，留空即可。
