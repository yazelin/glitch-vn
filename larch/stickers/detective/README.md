# 格莉奇・偵探小說家（Larch 表情包）

27 張透明表情素材，角色是《格莉奇與黑洞先生》的格莉奇。

## 這包在講什麼

**格莉奇在寫偵探小說，而且寫不完。**

她講話用偵探的腔調，推的卻是自己的稿子。每一句聽起來像在審問嫌犯的台詞，
其實都是對著自己寫壞的章節講的：「兇手居然是我」是寫到一半發現伏筆是自己埋壞的，
「時間線對不上！」是自己的章節時序兜不攏，「動機是什麼？」問的是她筆下那個角色為什麼要做那件事，
而她自己也答不出來。

這是偵探小說家的日常，不是偵探的日常。她沒有案子可破，只有一份交不出去的稿。

## 兩段式

**前 18 張是偵探腔。** 放大鏡、格紋偵探帽、記事本、打字機、身後一整面紅線板。
可以當純推理梗的貼圖用，跟創作完全無關的場合也接得上。

**後 9 張回到創作現場。** 筆電、繪圖板、耳機、瀏覽器分頁，句子也換成創作者的話：
「這趴我要修十遍」「分歧選項怎麼選」「卡稿中求救靈感」。

所以同一包能走兩種用法：推理梗，或者創作者之間互相取暖。在 Larch 社群裡討論劇本、
分歧、卡稿的時候，後半段那九張是主力。

## 兩張「真相只有一個」

`09` 與 `10` 是同一句話的兩種語氣：一張冷靜宣告，一張崩潰大吼。
留兩張是刻意的——那句話在寫得順的時候跟寫不出來的時候意思完全不一樣。

## 畫風

薄荷到薰衣草的漸層短髮、兩枚會發光的天線髮飾、左側銀色髮夾、黑 choker、
寬鬆連帽衣配深藍內領、胸前深紅 ERROR 徽章。淡彩動畫上色。

**現行這 27 張是 v2，比《格莉奇與黑洞先生》正篇的立繪更圓更可愛一點**，
因為是另一套生圖管線畫的（見下面「為什麼整包重畫」）。作者 2026-09-11 拍板接受這個差異：
「反正是貼圖」。跟站上其他素材並排會有接縫，這是知情的取捨。

## 封面

`cover.webp`（1536×1024）。凌晨的書桌，她戴著格紋偵探帽整張臉趴死在打字機上，
一隻手還舉著放大鏡，桌上與地上全是揉爛的稿紙，身後的紅線板纏成一團解不開，
有兩條紅線垂到她頭上。刻意不放任何文字，中央留白，裁成正方形也讀得出來。

用 `.11` 的 codex-image-service 產的，參考圖是 `01`、`04`、`18` 三張。

## 為什麼整包重畫（v1 → v2，2026-09-11）

**v1 有 24 張的頭頂被切掉。** 每張的上緣留白都精準是 10px、左右留白左右對稱，
代表 Larch 的透明貼圖產生器是「裁到內容邊界再補 10px」，而切口在生成當下就發生了。
量最上面那一列不透明像素，幾乎每張都是一段 20 到 150px 的平切：多數是右邊天線水晶的
頂端被削平，13／16／26 是連頭髮整片削平，18 的偵探帽、25 的耳機、23 的天線也中。
只有 04、19、22 是完整的。

**先試過只補頭頂，不通。** 把圖上方補 90px 空白送 `.11`，指名只補畫缺掉的部分、
下面每個像素都不要動，回來的是整張重畫：線條變粗、眼睛畫法不同、ERROR 徽章不見了。
`POST /api/agent/projects/:id/images/generate` 也接不上，它回白底無 alpha 而且不吃參考圖
（`input_images` 永遠是 0）。做出 v1 的那個透明貼圖產生器是網頁功能，沒有 agent 端點。
結論是只要由 agent 重畫就一定換畫風，所以三張沒被切到的也一起重做，整包才會一致。

**做法：3×3 貼圖表，三張表。** `v2/gen.py` 走 `.11` codex-image-service，
一次九格、純綠幕 `#00FF00`、參考圖三張。提示詞第一行就是畫布規則，並明寫
「參考圖全部被切在頂端，那個裁切就是你要修的錯誤，不要重蹈」。
`v2/build.py` 切九格 → `cutout.py key` 去背 → premultiplied alpha 縮放 → 再 despill 一次。

**幕色選綠的理由**：頭髮是低飽和淡青、水晶是青綠，離純綠都比離洋紅或橘遠；
而且第一次用橘底時模型自己加了黃色驚嘆線，跟橘幕太近。

**v2 的驗收數字**：上留白最小 16px（v1 是 10px 且內容貼齊切口）；頂列平切段中位數 9px、
最大 29px（v1 最大 150px）；四角全透明 27/27；殘留綠邊 25 張是 0、兩張各 1px；
主體內部半透明最大 150px（超過 1500 才算有整片被吃掉）；三張表都沒有內容碰到外框，
切出來沒有鄰格碎片。

**順帶解掉的事**：v1 的 `20` 與 `26` 筆電上有蘋果標誌，當時是用線性內插補回蓋子漸層、
再畫一根香蕉蓋上去。v2 的筆電本來就是貓頭標誌，這個補丁不再需要。
v1 全套（含香蕉版）留在 `v1/`。

## 尺寸與格式

**370×320 RGBA，27 張全部一致。** 這不是隨便挑的數字：Larch 上已經上架的
「格莉奇與黑洞先生-表情包」那 18 張抓下來量也是 370×320，所以這是平台表情素材的原生尺寸，
不要再縮放。

**存成無損 WebP**，共 2.6 MB。當初從 PNG 轉檔時逐像素比對過：alpha 完全相同、
alpha 大於 0 的區域 RGB 最大差 0，唯一的差異在全透明像素底下那層看不到的 RGB。
有損 q92 只要 0.7 MB，但半透明邊緣像素的 RGB 最大偏差到 221，會有鑲邊風險，所以不用。

**平台吃 WebP。** 2026-09-11 在沙盒專案 `project-5aae449c…` 實傳過一張
（`POST /media`，`mimeType: image/webp`，`category: prop`），回 200 並在 R2 上以 `.webp` 供應，
測試檔已清掉。

上傳時中文檔名會被洗成底線（實測 `__webp測試.webp` → `1789116528045___webp__.webp`），
不過那只影響 R2 的網址，JSON 裡的 `name` 欄位原樣保留，所以顯示名稱照樣用中文。
